## 关键行为

- 角色模板的编辑创建不可变版本；世界角色明确绑定版本。同模板的不同世界实例拥有不同 ID，不查询其他世界或其他房间历史。跨房间的合法长期记忆待 T07 实现。
- 接收用户消息时固定受众；后续加入的角色不会获得先前消息，包括已排队但尚未执行的输入。新回复受众取原输入受众与当前成员的交集。
- 每名发言者独立编译 prompt。先过滤可见世界书/状态/消息，再做关键词激活与预算处理。必需人设/玩家身份/本轮输入放不下时，零模型调用并明确失败。
- 发言计划固定到 run；种子为客户端命令 UUID。显式点名最多取前三位；未点名按最近发言、参与度、固定种子排序。参与度为 0 时不自动入选，仍允许明确点名。这里的最近发言轮换不是自然时间调度。
- 一个 run 的多角色步骤共用世界命令顺序。步骤完成后释放租约并持久排队下一步；崩溃不会重新生成已完成角色。后续步骤失败/取消时，之前已经提交的消息和声称仍保留。
- 生成提交前核对世界配置修订。期间编辑设定或成员会使旧输出标记 `context_changed`，不能成为已完成剧情。整轮默认共用 120 秒上限，可由 `MODEL_TIMEOUT_MS` 配置；每个模型请求单独预留额度和结算 usage。
- 模型文本仅生成 `character_claim`，不自动修改客观状态。用户可编辑受限的地点、剧情时间、在场角色和未完成话题，并设置可知角色；保存产生可追溯纠正事件。
- 重生成仅允许世界中最后一个已完成、无后续命令/配置/纠正依赖、无外部副作用标记的运行。旧消息和声称失效，新 run 关联旧 run；重复命令返回同一 ACK。T07 引入派生记忆后必须同步失效，T09 接入真实工具后必须设置副作用保护，当前没有声称这些未来模块已经实现。
- 编辑/移除使用 `If-Match`。客户端 409 时保留草稿并展示服务器版本，由用户选择采用新版本或明确重新保存。世界/房间/角色的移除是工作区软删除，不宣称已完成 T07 的隐私擦除或 T12 的备份清除。
- Apple 会话仅存 Keychain。缓存键由规范化 URL、实例 ID、恢复 epoch、owner 组成；切换立即清空当前显示，原草稿/命令保留在原命名空间，不能自动投递到新实例。待发送顺序使用本地递增序号，消息顺序使用服务端游标。
- SSE 按字节解析，保留空行帧分隔和跨字节中文；每次提交同时保存缓存与游标。重连先补拉增量；过期游标重建缓存但保留草稿和待发送。收到 ACK 只表示服务器已接收，不显示为模型已完成。
- 新客户端使用 10 分钟有效、固定高水位的分页快照，每页最多 500 项。快照完成后从高水位追平；Worker 每分钟清理过期快照及超过 7 天的同步事件，原消息不随事件清理删除。P1 的整份快照端点保留兼容。

联调中发现并修复：无签名 iOS 包写入 Keychain 失败（UI 测试改为本地签名）；SSE 空行分隔被行迭代遗漏（改为按字节解析）；多轮历史下重启聊天可能停留在顶部（改用声明式 `ScrollPosition` 底部定位，并跟随待发送队列变化）；消息无障碍分组区分正文与完成状态；并发过期请求避免重复轮换同一凭证。

- 没有真实模型 Key，不能宣称人设效果或两家供应商兼容已验收。所有模型返回均为合成服务。
