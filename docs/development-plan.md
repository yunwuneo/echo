# 开发计划 v0.1

更新日期：2026-10-11。状态：已实现至 P5（T11–T12），证据与待验收项见 [P5 实施记录](p5-report.md)。本文为总计划，任务细节、协议语义及验收数据分别见链接文档。

## 1. 需求理解

### 核心目标

开发 iOS/macOS 双端的多角色陪伴与剧情应用，服务端开源自部署，云端统一管理消息、人设、世界书、记忆和剧情。全部客户端关闭后，服务器仍可按授权整理记忆、让角色主动联系用户、进行有限的角色间互动及调用外部 MCP 工具。

已与用户确认：主要服务中国大陆用户；每实例一个主人、多设备；用户输入服务端 API URL 并自带模型 Key；首版不做订阅、运营或开放注册；接受可选的无正文推送中继；MCP 首版只有向外调用方向。

### 显性与隐性需求

| 类型      | 内容                                                                                                                                               |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 必须      | 双端、云端权威、单主人认证、多角色/群聊、人设、世界书、记忆、主动消息、有限离线剧情、外部 MCP、可控开关与预算、离线回顾、自部署文档                |
| 隐性      | 关闭客户端仍完成任务、断线恢复、跨设备一致性、用户现实资料与虚构身份隔离、角色知识隔离、世界状态版本、来源追踪、凭据管理、恢复后避免双实例重复执行 |
| 边界      | 设备强退不等于云任务取消；APNs 接受不等于送达；MCP 写入超时可能已发生副作用；模型声称不是客观剧情；删除来源会影响派生记忆                          |
| 可选/后续 | 多模态、语音、角色市场、多用户托管、收费、Android/Web、复杂导演模型、MCP Server、通用电脑控制、完整历史分支与全套酒馆插件兼容                      |

### 合理假设

- 首版以文本体验为主，包含角色头像，暂不做图片理解/语音通话。
- 一个世界包含多个角色和房间；同一模板在不同世界中是独立实例。
- 采用 iOS 18/macOS 15 起的原生实现，使用普通 HTTPS 模型 API；最低系统版本是推荐而非用户既有约束。
- 主人能管理整个实例，但角色只能知道其可见信息。
- 用户自行承担其模型 API 消耗；软件提供用量、预算和暂停能力，不建设收费系统。
- 首版世界可在无人参与时有限推进，但不无限模拟，也不默认代用户做现实操作。

完整范围及数值默认值见 [产品与决策](product-and-decisions.md)。

## 3. 推荐技术方案

### 架构选择

- 客户端：SwiftUI + 共享 Swift Package，平台分别适配；本地仅缓存和草稿。
- 后端：TypeScript/Fastify 模块化单体；API 与 Worker 分进程，使用同一业务模块。
- 存储：PostgreSQL + pgvector，pg-boss 持久任务，事务 outbox；资源用数据卷，首版不引入 Redis/MinIO/独立向量库。
- 协议：OpenAPI 生成类型；REST 命令 + 持久游标 SSE + REST 增量恢复。
- 部署：Docker Compose + HTTPS；可选的无正文 APNs 中继。
- AI：模型供应商适配层 + 自己控制的 RunEngine/PromptCompiler；用标准 MCP SDK，不把核心世界状态交给第三方通用 Agent 框架。

关键选择理由：两个 Apple 客户端优先原生体验；云端任务独立于界面；一实例一个主人适合小规模单体；同一数据库减少个人部署和恢复负担；服务端统一领域规则避免两端各写一套记忆、剧情和工具逻辑。

### 核心数据流

用户命令 → API 鉴权并幂等落库 → outbox/持久队列 → 世界级顺序执行 → 按当前角色过滤知识 → 世界书/记忆/近期消息组成上下文 → 模型/工具 → 保存消息和世界事件 → 更新客户端 → 异步整理记忆与回顾。

自主触发从调度器进入同一条执行链。推送只发生在消息保存之后；不负责驱动生成，也不承载权威消息数据。

### 关键设计必须一次定清

1. 角色模板、世界内角色实例、玩家 Persona 是不同实体。
2. 世界书、已确认世界状态、角色记忆是不同来源与信任程度的数据。
3. 私聊秘密通过数据库/检索权限隔离，不仅在提示词里告诉角色“不要泄露”。
4. 同一世界顺序提交，用户命令优先；外部调用不持有数据库事务锁。
5. 主动发消息、角色间剧情互动、现实工具读写分别授权。
6. 工具未知结果不自动重试；重生成剧情不重放现实副作用。
7. 所有后台工作含记忆和摘要都纳入预算；关闭开关检查覆盖启动和提交阶段。

详细数据模型、接口族、状态机、数据权限、导入映射原则见 [技术架构](architecture.md)。

## 6. 测试与验收标准

### 必须通过的端到端故事

1. iPhone 创建世界并群聊，Mac 获取同一角色、消息、记忆与剧情状态。
2. 用户告诉角色 A 一个秘密，角色 B 在同世界其他房间和群聊中均无法通过上下文、向量检索、摘要或世界书得知它。
3. 关闭 iPhone/Mac App，服务器执行一轮获准互动；重新打开后看到已保存的原始消息与准确回顾。
4. 将自主开关关闭，正在排队的任务不再开始，迟到结果不发布新的剧情；已发送的外部请求准确报告状态。
5. 在流式生成中断网或重启 Worker，恢复后正文/状态一致，无重复完成消息，不将半截文本标成成功。
6. MCP 写操作需要符合授权；超时未知结果不被自动重试，剧情重生成不重复执行外部动作。
7. 从备份在全新环境恢复，校验数据和凭据，完成重新配对；旧实例不同时继续自主运行。

### 验收指标

- 确定性权限、幂等、数据完整性、取消与预算测试全部通过，失败零容忍。
- 合成中文检索样本的 recall@5 目标 ≥ 90%；无来源事实写入与越权记忆读取为 0。
- 固定剧本的人设一致性评分目标 ≥ 4/5；真实模型评估记录供应商、模型和 prompt 版本，不把一次手测作为结论。
- 网络正常且服务器空闲时，命令持久化 ACK 目标 p95 ≤ 500ms、已提交变更到另一在线端可见 p95 ≤ 2s；模型首 token/完成时间独立统计，不混入服务器自有开销保证。
- 2 vCPU/4 GiB 基准环境、指定合成数据集下验证；达不到先定位和调整指标/容量，不宣称未经测试的 SLA。
- 真机 APNs 分别测试前台、后台、锁屏、关闭权限、强退、离线与中继不可用；不能以模拟器或 HTTP 200 代替最终行为记录。

完整案例、测试数据量、故障矩阵和评估口径见 [验收方案](acceptance.md)。

## 7. 风险与注意事项

| 风险                               | 措施与回滚                                                                                         |
| ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| 多角色共享上下文导致秘密泄漏       | 数据访问先过滤再召回；按角色构建 prompt；污染派生数据失效；关闭受影响世界自主模式                  |
| 角色声称污染世界事实，剧情逐渐偏离 | 事件类型、证据与人工纠正优先；回顾可追溯；受限重生成，不自动时间旅行                               |
| 自主循环和费用失控                 | 规则先过滤、持久预算预留、每轮/每日上限、禁止自动任务无限衍生；一键停后台                          |
| MCP 写入重复或误操作               | 参数绑定授权、显式审批、未知结果不重试；真正副作用只通过目标系统补偿，不能假称聊天回滚已撤销       |
| 服务器重启/并发产生重复剧情        | 持久队列、outbox、租约栅栏、状态 CAS、唯一键、故障注入                                             |
| 模型/嵌入服务在用户环境不可用      | 可配置端点、能力探测、超时/熔断、词项检索降级；不依赖未声明的跨境连接                              |
| 自部署端点与 MCP SSRF/凭据泄漏     | HTTPS、凭据加密、出站地址校验、按连接内网许可、日志脱敏                                            |
| APNs 依赖与中继滥用                | 中继可选、票据撤销和限速、无正文；通知失败不影响数据；禁用中继后客户端同步仍可用                   |
| 数据迁移与备份丢密钥               | 版本化备份、主密钥独立保管、隔离恢复验证、维护模式切换；必要时恢复旧备份而非盲目逆迁移             |
| 竞品格式/许可证不兼容              | 声明兼容子集、保留原始扩展、独立实现；复制代码前检查许可，不默认豁免                               |
| 大陆分发条件与隐私声明             | 在选定分发路径后核实当前 App 上架、备案和隐私要求；自部署不自动消除客户端/中继责任，发布前单独完成 |
