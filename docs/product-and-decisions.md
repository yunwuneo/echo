## 2. 推荐产品定义

项目对外名称统一为 Echo，包括客户端显示名、窗口标题、README 和 API 文档标题。现有本地目录、数据库/Compose 标识、Bundle ID、Keychain 和缓存键保留历史标识，以保持已有数据与配对兼容；它们不作为产品名称展示。

2026-10-11 用户明确要求界面中的“世界 / 世界书”改称“TA 的设定 / 设定集”。本文及架构、接口、迁移中的“世界”仍指原有共享世界领域，`world` / `lore` 标识保留；界面命名不将共享世界变为单角色私有配置，不合并同一模板在不同世界中的经历。

一款可自部署、在云端持续运行的多角色陪伴与剧情应用。用户创建或导入角色，建立世界，在私聊和群聊中共同经历事件；角色保留各自的经历和知识。在用户允许的世界中，有限的后台互动可以推进剧情，并在用户回来时提供可追溯的回顾。

“持续运行”是持久化任务和按需唤醒，不是不断调用模型，也不要求每个角色对应一个常驻容器。

### 核心体验流程

1. 部署服务器，App 输入 HTTPS URL，通过一次性配对码绑定设备。
2. 配置聊天模型及 API Key，选择可选的嵌入模型，验证服务能力。
3. 新建世界、导入/编辑角色与世界书，设置用户在这个世界中的身份。
4. 创建私聊或群聊，选择参与者；发送消息后能看出由谁回应。
5. 查看“记住了什么”和“当前剧情”，修正错误记忆及世界事实。
6. 开启世界的自主模式，分别配置主动联系、角色间互动和工具权限。
7. 关闭全部客户端。云端继续执行获准任务；回来后从回顾跳转到真实事件。

### 当前信息架构

- iOS 一级入口为“聊天 / 回忆 / TA / 我”：聊天列表与搜索；有真实来源的记忆时间线；按世界内角色实例切换的资料与设定；服务器、通知、外观及高级管理。
- 聊天详情隐藏 Dock，保留私聊、群聊、点名、剧情与回顾、记忆和行动确认；技术配置集中到资料/设定与“我”的高级入口。
- “TA 的设定”继续容纳共享世界中的角色、设定集、剧情、主动消息及权限；全局预算、MCP 与诊断不因首页改版而移除。
- 只从真实运行和审批派生实时状态；未读数量、在线/已读、纪念日等缺少数据来源时不展示。
- macOS 保持侧栏、对话与详情栏。两端共享领域与网络层，分别适配界面；系统版本差异与实现证据见 ADR-021。

### 首版必须交付

- 单主人配对认证、设备撤销、端点切换和多端增量同步。
- 文本聊天、基础头像、Markdown 安全渲染、持续群聊、点名回应与有限多角色接力。
- 角色模板与世界内角色实例、人类玩家身份；角色设置版本化。
- 世界书 CRUD、关键词/常驻/安全正则触发、优先级、扫描深度、注入位置及预算。
- 角色卡和世界书导入的明确兼容子集；失败或不支持字段可见，保留原始数据。
- 有来源、作用域和修订记录的记忆；用户可查看、修改、删除；处理过期和冲突。
- 私有知识隔离；角色所说的话与世界已经发生的事实分开。
- 后台记忆整理、主动联系、角色间有限互动、离线回顾。
- 外部远程 MCP 工具、权限控制、待批准状态、执行记录和超时恢复。
- 可选推送中继；不启用时所有业务仍可运行，回到 App 后同步。
- Docker Compose 部署、备份恢复、升级说明和诊断信息。

### 首版明确不做

订阅、支付、运营后台、开放多用户注册、角色市场、公开社交分享、Android/Web 客户端、3D/Live2D、语音通话、视频生成、通用电脑控制、任意 npm/stdio 服务上传执行、对外 MCP Server、完整酒馆脚本/插件兼容、完整分支宇宙与任意历史回滚。

图片/语音等多模态聊天可后续扩展；当前不为其增加首版上传和推理链路。角色头像属于首版基础资源。

## 3. 架构负责人推荐决策

以下为可执行的推荐基线。若用户后续无相反要求，进入开发后按此实现；不将其表述为用户亲自指定的技术栈。

| ADR | 决策与理由                                                         | 替代方案与取舍                                                                                             |
| --- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 001 | SwiftUI 双平台、共享 Swift Package；推荐最低 iOS 18 / macOS 15     | Flutter 更适合五端覆盖；当前仅 Apple 平台，原生通知、钥匙串与桌面交互更直接。最低系统是建议，可在 T00 调整 |
| 002 | TypeScript + Fastify 模块化单体，共享代码的 API/Worker 两进程      | Python 可行，但首版没有自训练算法；不引入第二套服务语言或通用 Agent 框架                                   |
| 003 | PostgreSQL + pgvector + pg-boss；单数据库保存业务、任务及同步事件  | SQLite 适合单机，但多进程持久任务和并发状态更适合 PostgreSQL；Redis/独立向量库暂不增加                     |
| 004 | 云端权威，客户端 SwiftData 仅缓存、草稿和待发送队列                | 不用 iCloud 作为第二个同步源；不做离线本地推理或双主 CRDT                                                  |
| 005 | 同一世界的剧情写入按顺序执行，不同世界可并行                       | 角色并行生成更快，但世界事实、知识与工具操作更容易冲突；先保证一致性                                       |
| 006 | 角色模板与世界内实例分开；真实用户资料与虚构玩家身份分开           | 简单全局角色记忆会导致不同剧本串线，不适合本产品                                                           |
| 007 | 规则挑选发言者 + 每个发言者独立上下文，有限接力                    | 一次模型扮演全体角色会暴露所有私有知识；全模型导演每轮都付额外成本；复杂导演后续由效果评估决定             |
| 008 | 世界书为显式设定，记忆为带证据的经历，世界状态为已确认剧情事实     | 不把三者压成一个无限增长的系统提示词，也不让摘要替代原始事件                                               |
| 009 | 任务至少一次投递 + 幂等提交 + fencing token；显式处理工具结果未知  | 不承诺模型与第三方副作用“恰好一次”；不在外部调用期间持有数据库事务锁                                       |
| 010 | MCP 首版支持远程 Streamable HTTP，兼容旧 HTTP+SSE 作为独立适配任务 | STDIO 涉及云端任意进程执行，首版不支持；工具 API 仍保留协议无关内部接口                                    |
| 011 | 可选无正文推送中继；核心数据和业务不依赖中继                       | 自签名用户可以部署自己的中继并配置自己的 APNs；不能分发官方 App 的 APNs 私钥                               |
| 012 | API Key 在用户服务器可用并加密保存，客户端设备凭证在 Keychain      | 仅把模型 Key 留在手机无法支持离线云端运行。云端解密执行与“服务器完全无法读取”的端到端加密无法同时直接成立  |
| 013 | 持久化命令、当前状态、领域事件与修订记录；不建设完整事件溯源框架   | 保留恢复和追踪能力，但不把任意时点重放整个世界作为首版目标                                                 |

## 4. 首版运行默认值

这些是可配置的保守起点，不是实测性能结论。

| 设置         | 默认与限制                                                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 自主模式     | 全局关闭；每世界也默认关闭；开启总开关不会隐式开启所有世界                                                                                        |
| 群聊         | 每个房间最多 8 个角色；一次用户输入最多触发 3 条角色消息；优先明确点名，否则参与度、最近发言和冷却规则选择                                        |
| 无人互动     | 每世界每次最多 3 条角色消息、每天最多 4 次互动；全实例同时最多 1 次无人互动                                                                       |
| 主动联系     | 每世界每天最多 3 次、最短间隔 2 小时；默认安静时段 22:30–08:00，使用用户设定时区                                                                  |
| 全局后台预算 | 初始每天最多 20 次模型请求、100,000 输入 token、10,000 输出 token；适用于自动记忆、自动摘要、自主联系与剧情。可单独调整各项，前台请求另有显式限制 |
| 后台预算占满 | 暂停非必要后台生成；保留用户可见状态和手动重试，不静默增加预算                                                                                    |
| 调度         | 每分钟扫描已到期任务，不为每个角色每分钟调用一次模型；错过窗口只重新评估一次，不补发过期消息洪峰                                                  |
| 工具         | 未授权默认不可调用；读取也按连接和工具授权。现实写入默认逐次批准；允许用户建立狭窄、可撤销的长期授权                                              |
| 工具循环     | 单次运行最多 4 次工具调用；默认单次外部请求 30 秒超时，整次运行 120 秒上限，平台取消不保证撤销外部副作用                                          |
| 通知         | 默认通用文案；无正文、角色名称或剧情摘要；仅有限投递标识和路由所需信息                                                                            |
| 记忆         | 明确的用户纠正立即生效；后台整理目标为可运行且预算允许时 5 分钟内完成，失败不阻塞聊天                                                             |

## 5. 仍需用户后续决定，但不影响当前架构

- 首批示例世界；视觉风格已按 ADR-020 采用用户提供的暖色参考。
- 客户端是否也开源；服务端和客户端具体许可证。推荐先评估 AGPL-3.0 的服务端方案，但本次不创建 LICENSE 或替用户作法律承诺。
- 最初的分发方式和 Apple Developer 团队：建议先 TestFlight/内测，再完成中国大陆上架所需事项。

首版模型默认不绑定某一家供应商。开发阶段用用户选择的至少两种 OpenAI-compatible 服务做兼容验证，准确记录实际能力；未提供有效 Key 时可以完成模拟服务测试，不能宣称真实模型效果已验收。

## 6. 进入实现后的 ADR 补充（2026-10-10）

### ADR-014：P1 交付与协议基线

- 状态：已采用（用户授权 P0–P1；具体工程选择沿用负责人推荐）。
- 决策：固定 Node 24.14.0 / npm 11.9.0、PostgreSQL 17 / pgvector 0.8.2；Swift 构建工具需 6.2+，部署系统仍为 iOS 18 / macOS 15。TypeBox 生成 OpenAPI，Apple 使用固定官方生成器 1.14.0、运行时 1.13.0、URLSession 1.3.2；npm 和 SPM 锁文件记录传递依赖。
- 理由：容器保证后端工具链可重建；所选 Swift 组合避免旧运行时的 unsafe flags 限制，并与生成器的最低运行时一致。
- 替代：使用本机 Node 25/PostgreSQL 18 或手写 Swift REST 模型，均不作为 P1 验收基线。
- 影响：P1 交付服务器文本协议测试助手及本机 seed 命令；角色/群聊/上下文编译仍按 T04–T06 实现，首版产品范围不变。会话使用数据库哈希保存的随机访问/刷新令牌；刷新重用撤销轮换链。凭据使用 AES-256-GCM 并绑定 owner、连接 ID 和密钥版本。
- 未决：许可证继续待定，不创建 LICENSE、不发布源码；真实模型与 Apple 分发/通知条件不阻塞模拟协议验收。

### ADR-015：P2 角色上下文与客户端同步

- 状态：已采用（2026-10-11；用户授权 P2）。
- 决策：同一 run 保存固定发言计划、步骤索引和每步尝试；每步独立模型上下文/usage，最多三步，共用总期限与世界顺序。接收消息时固定角色受众，角色设定版本/配置修订保留历史。角色文本为声称，客观剧情仅接受受限的用户确认/纠正。
- 理由：复用 P1 队列、outbox 和 fencing，避免第二套编排；成员变化不能扩大既有消息权限，迟到结果不能覆盖新的设定。
- 替代：一次模型输出多角色、按当前成员回溯授权、将角色说法直接合并事实，均无法满足独立知识与恢复要求。
- 客户端：共享 SwiftUI 业务视图、生成 REST、Keychain、SwiftData；按服务器 URL/instance/epoch/owner 隔离缓存和命令。SSE 按字节保留空行分帧；固定水位分页快照有效 10 分钟，增量事件保留 7 天。
- 影响：P2 的世界/房间移除为软删除；T07 加入记忆后须接入重生成/隐私删除的派生失效，T09 加入真实工具后须写入副作用保护。快照构建与大数据缓存的容量优化以 T13 实测为准。
- 未决：Mac UI 自动化环境、完整无障碍回归、真机、真实模型效果和发行签名仍按 [实施记录](p2-report.md) 留待验证。Debug 的 loopback HTTP 只用于用户已授权的本机合成测试，Release 仍要求 HTTPS。

### ADR-016：P3 有来源记忆、失效屏障与兼容导入

- 状态：已采用（2026-10-11；用户明确授权 P3，T07–T08）。
- 决策：记忆按已完成消息独立游标、房间持久任务整理；逐字摘录与引用 schema 校验，受众取来源交集。用户陈述不冒充客观事实，角色声称始终保留不确定性；不同内容同主题进入冲突，人工选择替代。修订、来源、词项和版本化 pgvector 向量均保存在现有 PostgreSQL。
- 理由：无真实模型基准时，以可核对证据约束自动提取；不让模型凭空扩展角色知识或覆盖用户纠正。未配置嵌入、重建或服务失败时继续词项检索。
- 遗忘：世界 memory_epoch 栅栏拒绝旧提取/索引；跟随实际 prompt 来源依赖保守失效后代，清理向量与记忆修订，强制旧游标重建并销毁快照。删除原文额外擦除依赖消息；不会声称可以撤回第三方模型已接收数据或清除离线设备尚未重连的缓存。
- 世界书：RE2-WASM 1.0.2 提供安全正则；按房间/角色/条目版本的成功回复推进 delay/sticky/cooldown，与 Manifest 和最终消息同事务提交。当前条目集合保持扁平组织，导入批次关联原件，不增加独立世界书容器 UI。
- 导入：v2/v3 JSON/PNG 与已声明世界书字段子集先预览后确认，支持跳过/复制冲突。按原始文件 SHA-256、目标世界和适配器版本幂等；原件按字节保存，未知扩展可下载。未支持触发条件的条目停用；不执行脚本、宏或请求远程资源。
- 替代：自由改写自动事实、自动覆盖近似冲突、无权限边界的向量搜索、JavaScript 任意正则、自动下载卡片资源均不采用。索引使用精确距离检索，达到容量瓶颈再评估 ANN。
- 影响：世界默认不开自动记忆；提取与嵌入共用保守后台预留预算，当前按 UTC 日结，P4 统一接入自主总开关、类别与用户时区。词项召回评测和模拟协议不替代真实模型效果；完整使用限制见 [P3 使用说明](p3-usage.md)。

### ADR-017：P4 持久工具检查点与有界自主运行

- 状态：已采用（2026-10-11；用户明确授权 P4，T09–T10）。
- 决策：使用官方 MCP SDK 1.32.1 的远程 HTTP/SSE，外覆固定 DNS 地址、同 origin、拒绝重定向和响应上限的受控 fetch。只提供有限 schema 子集，未知约束使工具不可调用。权限由实例/世界工具开关和角色 grant 决定，工具的只读提示不作为证据。
- 恢复：每次工具提出/批准/dispatch/结果均落库；审批冻结参数、schema、授权、连接和世界/策略修订。审批暂停不占世界租约，恢复后重新核验。未知结果人工核对，不自动重放；取消已发请求只记录不确定性，不承诺撤销。审批决定和授权快照留作审计，完整工具结果不进入普通日志。
- 自主：统一记忆/嵌入、主动联系及角色互动的总开关、世界/类别开关、IANA 时区与预算，默认关闭。前台工具使用独立工具开关；开启后台剧情不等于开启现实写入。后台生成使用同一个 RunEngine，用户在发言边界优先，错过的时间窗不追补。
- 回顾：先交付可跳原文的确定性消息摘录，避免没有真实模型质量证据时引入额外摘要事实与费用。摘要模型可在后续有质量基准时扩充，不影响离线回顾首版能力。
- 替代：任意 JSON schema 编译/远程引用、全局放行内网、HTTP 请求透明重试、自动回滚现实副作用和额外导演服务均不采用。
- 影响：P3 已开启的记忆设置继续保存，但 P4 新增总开关和世界记忆类别默认关闭，需主人明确开启；预算从 UTC 日切换为配置时区，历史用量保留。具体协议、schema 子集、精确 IP 许可与活动列表限制见 [P4 使用说明](p4-usage.md)。
- 未决：真实供应商和远程 MCP 兼容、24 小时墙钟压力/容量、真机与完整 Mac UI 验证，不能以模拟协议/虚拟时钟代替。许可证和 Apple 分发仍按原决定待定。

### ADR-018：P5 可选通知票据与停服恢复

- 状态：已采用（2026-10-11；用户“继续进行 P5 的实现”授权 T11–T12）。用户表示已有 Apple 团队和签名环境，将稍后提供；无真机通过声明。
- 通知：可选独立中继进程，按环境隔离、topic 白名单；邀请与服务器一次性 challenge 共同绑定设备、实例、epoch。随机票据在业务库加密、中继只存哈希；APNs token 在中继库加密。固定通用 alert，不接收聊天、角色、记忆或模型 Key。不开中继不影响业务。
- 投递：完整消息与投递 outbox 同事务保存，网络在独立异步循环；同 delivery ID 幂等、dispatch 前持久化。中继到 APNs 的未知结果不透明重放；接受与显示分开。静默时段不推送，失效 token 撤销绑定；客户端点击先身份校验、认证解析、同步再跳原文。
- 运维：活 API/Worker 持共享数据库 advisory lock，密钥轮换/恢复操作需停服、维护状态和独占锁。备份使用标准 pg_dump，自带格式/校验和/数据清单，排除可重建队列；所有原件和头像当前存数据库，无第二个资源存储。
- 恢复：只接受空隔离库，核验后换 epoch、撤销设备、停用自主/MCP/推送、中断旧 run，保留现实副作用未知状态。最新删除 ID 清单可重新应用于旧备份。保持维护直到操作者停源并显式切换，不宣称能够自动证明异机旧实例已经关闭。
- 导出：owner JSON archive 是查阅/迁移格式，含角色版本、来源和原件，但无应用凭据；规范化 data 的 SHA-256 不依赖 JSON 键顺序。整实例恢复使用数据库备份，不从公网执行 restore。
- 替代：静默推送驱动业务、裸 device token 直接授权任意服务器、分发官方 APNs 私钥、未知投递无限重试、在线换 Key 与直接覆盖生产库均不采用。
- 影响：备份有停服窗口；主密钥独立保存，旧备份需对应旧密钥。当前第一版归档 v1，没有既有正式旧归档格式。独立中继允许 iOS/macOS 多 topic，同环境共享一套 APNs key；测试/生产分别部署。实际配置、留存及验收范围见通知/恢复指南。

### ADR-021：系统 Dock、类型化展示状态与界面命名

- 状态：已采用（2026-10-11，用户要求继续根据 v2 设计规范和效果图更新并测试）。
- 决策：iOS 使用“聊天 / 回忆 / TA / 我”四个系统 tab，聊天详情隐藏 Dock；macOS 保留侧栏。iOS 26.1+ 常规字号使用可禁用的系统 bottom accessory 与 inline 短文案，辅助功能字号使用列表顶部可换行 QuietStatus；iOS 26.0 保留系统玻璃 Dock 但把状态放列表顶部，iOS 18–25 使用普通系统 tab bar 与相同列表状态。
- 理由：导航玻璃由系统适配外观与辅助功能；26.0 的外层条件挂载会改变 TabView 结构并重置页内状态，稳定空 accessory 又可能占位。26.1 的 `isEnabled` 重载可保持结构与安静的空闲态，本机 SDK 已核对其 availability。最大辅助字号实测被系统 accessory 的高度约束裁切，故使用可换行列表状态，保留用户选择的字体大小。
- 数据：消息/运行状态先从缓存投影为类型，未知值安全回退；实时状态只由真实运行、streaming 消息及有效审批派生。当前协议没有未读/已读、在线、纪念日或照片数据，不用样例填充。回忆按来源、世界与有效期展示，已打开详情按 ID 响应缓存删除/修订。
- 命名：面向用户统一“TA 的设定 / 设定集”，内部 `world` / `lore` 及服务端授权边界保持不变。多角色、群聊、共享世界和后台剧情仍为首版核心。
- 替代：自绘玻璃 Dock、重复 REST 获取展示状态、模拟输入/未读、按模板合并不同世界经历，以及在 26.0 状态切换时重建 TabView，均不采用。
- 影响：新增系统导航与页面投影、Asset Catalog 外观变体、中文 String Catalog、Apple UI lint；没有协议或数据库迁移。列表最新消息一次遍历聚合；连接切换与房间删除清理导航路径。
- 验证与未决：Core 最终 28 项及类型/静态/格式检查通过，iOS/macOS 最终代码构建通过，13 个 iOS 场景分批复测及 Mac 原生手测通过；历史系统、完整 VoiceOver 与真实输入动画仍待覆盖。证据见 [Dock v2 实施记录](ui-ux/2026-10-11/dock-v2.md)，不提前认定 T13 完成。官方接口见 [可禁用 accessory](<https://developer.apple.com/documentation/swiftui/view/tabviewbottomaccessory(isenabled:content:)>) 与 [inline placement](https://developer.apple.com/documentation/swiftui/tabviewbottomaccessoryplacement/inline)。

### ADR-023：首个本地里程碑的请求、文档与可恢复业务包

- 状态：采用，2026-10-14；依据用户继续完成 T01–T06 的授权。以下均为 Echo 实施补充，不推断 Aru 内部实现。
- 决策：继续复用现有云端权威、SQL 事务与原生导航。模型线路与提示配置在外部变量请求之前冻结；可选两小时回顾使用同一冻结线路、独立用量，默认关闭，成功后最多供两轮使用。模板日期/时间取固定服务端 UTC；必填变量失败禁止普通及嵌入模型请求。共享预设按引用更新，复制后独立。
- 文档：revision + 正文 hash 防覆盖，恢复历史创建新版本；当前及历史附件引用均受外键保护。内部文档工具沿用执行前批准和权限检查，业务写入与工具成功回执同事务；外部副作用仍可能 unknown，不承诺恰好一次。
- 备份：echo-encrypted v1 用 scrypt 派生密钥、AES-256-GCM 整包认证；manifest 包含源实例、owner、完整迁移名称及校验和。此版只接受匹配 schema，差异明确拒绝，需要显式格式迁移，不自动降级/丢字段。排除凭据、设备身份、队列、向量和临时请求诊断/回顾；密码不保存在服务器。
- 原子边界：完整 owner 业务关系图为一个对象，16 MiB 明文包、每表 10,000 行、小原件 1 MiB。OriginMap 与业务一起提交，失败后可从同一持久预览重试；不提供跨部分对象成功的假象。源包不修改，不复制大型落盘中间包；超限使用已有维护备份。成功回包丢失后返回已存结果。来源实例不同只重映射本地实体，保留远程目标 ID。
- 冲突与执行：本地变化拒绝旧预览；冲突需保留本地或取消，没有强制覆盖。恢复暂停授权、连接、计划和未结束作业，不生成 outbox；已有隐私删除禁止旧内容复活。新业务同步快照替换旧缓存。原生可读 JSON 含所选正文和原件，Markdown/PDF 是正文导出，均不替代加密包。
- 替代方案：未引入第二个数据库、对象存储或流式大包格式；它们需要额外部署与容量证据。未强制保留全部临时模型输入，避免普通诊断泄漏正文；请求快照独立认证加密，隐私擦除时清理。
- 影响与验证：013–020 为加法迁移，仅隔离合成库执行。强制测试包括真实终止测试库恢复连接后的回滚/续导、错误密码、schema/哈希错误、旧包冲突、重复工具调用、配置冻结和隐私擦除。最终结果与真实依赖边界见 [规格进度](app-spec-progress.md)，不视作发行验收通过。

### ADR-024：知识、创作与群协作的增量接入

状态：实现中/本地可运行；平台与真实依赖门槛按 `app-spec-progress.md` 单列。

沿用单权威 PostgreSQL、现有 worker、SwiftUI 和权限网关，新增 021–030 迁移，不建立第二套聊天编排。新世界书绑定受世界隔离；新导入只入库，新条目按消息时序，旧未归书条目保留轮次兼容。群工具必须明确选择并同时满足冻结配置和实时授权；群记忆默认关闭、最多一条成员私有资料。群解散擦除全部支线为本 App 实施补充，不能归为 Aru 已确认行为。相关差异由书库、群隔离和权限回归验证。

媒体作业以已持久化 intent/CAS/服务端任务 ID 恢复；接受结果未知时不自动重放。作品源码、状态与权限分开，恢复后关闭执行；旧 020 业务包通过明确的只加默认值转换器接入当前 schema，原始加密包不改写。备份不携带网络会话、执行队列、密钥或可重建索引。

Python 复用已有解释器：macOS kernel sandbox + 外部时间/输出/RSS 限制；Linux 使用 bubblewrap 与 rlimit，缺依赖失败关闭。macOS 采样 RSS 不等于硬峰值限额，WebKit CSP/会话隔离还须实测；不把这些实现描述成已完成安全认证。不引入 Docker socket 或下载容器镜像来执行用户源码。Linux 参数依据 [bubblewrap 官方说明](https://github.com/containers/bubblewrap)，其安全性取决于具体隔离参数，部署前仍须验证。

媒体 REST 适配依据供应商公开协议，当前只以合成服务做契约测试：[图片编辑](https://developers.openai.com/api/reference/resources/images/methods/edit)、[音频输出](https://developers.openai.com/api/reference/resources/audio/subresources/speech/methods/create)、[视频提交](https://developers.openai.com/api/reference/resources/videos/methods/create)、[视频查询](https://developers.openai.com/api/reference/resources/videos/methods/retrieve)。这些链接不构成真实线路已验证的证据。

### ADR-025：平台权限、独立 Host、可核对的远端副作用与协议扩展

状态：2026-10-14 随 T14–T20 增量实现；真实设备、远端服务与发布门槛仍独立验收。

1. Echo 云端仍是协调权威。本机系统动作在云端冻结参数、角色/设备授权和 revision，再由原生系统 API 执行。先写入按服务器/恢复 epoch 隔离的本机持久执行意图，成功后保存外部 ID。保存失败不执行；结果未知不重做。分享扩展只写 App Group 草稿；AskIntent 的直接发送必须由用户单独开启。
2. Host 是现有 Node 运行时的独立进程，使用自有 v1 协议、Ed25519 身份、一次性十分钟配对和逐动作/目录授权。对话调用 Host 自己的 Echo 实例及模型/MCP 网关，身份关联不搬运聊天数据库。直接 MCP 作业未宣称支持；远程对话中的 MCP 继续受 Host 自身现有网关检查。插件复用有界 Python 运行器，目录授权不会绕过其文件访问沙箱。
3. 代收只接入绑定身份的普通文字私聊；群、附件与不匹配身份明确返回 `relay_route_unsupported`，用户可明确关闭代收。节点签名确认 unsupported 且未接受时，才恢复原轮次的本地队列；accepted/unknown 不自动回退。接管使用单一权威 epoch、租约和撤销确认，超时不等于停止。明确撤销节点会原子失效令牌和 epoch；旧未知作业仍须用户核对结果、登记证据后才可接管。
4. 只发布用户选择的 fact/profile 版本快照；Host 收到的是只读文件 `shared-facts.json`，不自动写入 Host 记忆库。源版本变化或来源失效后，下一次同步发送失效标记及空内容。此设计避免把手机私有记忆混成 Host 的既有经历。
5. 外部文件采用授权根目录、拒绝符号链接、内容基线和协作写锁。外部读取先保留独立副本，明确写入才修改文件。进程崩溃遗留的 `.echo-lock` 不按年龄自动删除；管理员核实无写进程后处理。无法承诺防止同一 OS 用户恶意并发替换父目录；Host 授权根应由该 Host 管理，不能视作多租户安全边界。
6. 远端恢复点是 Echo 自有认证加密包，256 KiB 分块、完整 SHA-256 验证后发布 manifest，再按当前计划 revision 与 manifest revision 保留恢复点。旧包只读，恢复默认暂停/撤销所有执行。另设选定凭据加密包，绑定端点/协议/版本并显式导入，不混入聊天，也不自动探测。
7. Claude Messages、Gemini generateContent、Vertex Gemini 各有独立请求与流式解析；请求账本和 HTTP 共享同一构造函数。Vertex 使用用户提供的短期访问令牌和完整模型资源路径，不隐式创建云凭据。需要 thoughtSignature 的工具续轮明确不支持，不能丢签名后继续。媒体与 embedding 的非 OpenAI 线路未声明支持，必须显式选择支持的线路。
8. 诊断删除只清理符合预览的历史请求正文，保留最近完整请求、活动/未知动作与回执。逻辑字节和 PostgreSQL 分配空间分开显示，不自动 VACUUM FULL。系统通知已安排、本机运行机会和云端生成状态分开；macOS HealthKit/WeatherKit/电池、系统时钟 App 闹钟不伪装成可用能力。本 App 计时器使用通知，不承诺准点或强退后生成。

原始产品行为来自规格 F13–F18；上述安全边界、平台适配、包格式和不支持范围均为 Echo 实施补充。替代方案（自动把 unknown 当失败重发、双端独立接管、整库合并、默认凭据备份、复制 Aru 设计）被拒绝，因为会增加重复副作用、泄漏或不可恢复风险。

协议依据：[Claude streaming](https://platform.claude.com/docs/en/build-with-claude/streaming)、[Gemini generateContent](https://ai.google.dev/api/generate-content)、[Vertex inference](https://cloud.google.com/vertex-ai/generative-ai/docs/model-reference/inference)。平台依据：[HealthKit authorization](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)、[EventKit authorization](https://developer.apple.com/documentation/EventKit/EKAuthorizationStatus)。只依照协议资料实现，未据此宣称真实链路通过。

### ADR-026：完整规格复核中的执行证据与非破坏性默认

状态：2026-10-14 用户授权的本地增量修正，真实依赖单列。

系统和 Host 的不可变参数摘要在执行前复核；媒体首次提交重新检查硬性禁用，已经接受的任务只读查询不受新调用开关影响。Host 主动委托仍受云端全局和世界主动总开关约束。删除及恢复必须保留未决副作用的可对账路径。

备份预览先校验完整结构关系和受众，跨实例只重映射本地结构 ID；原始远端回执、执行标识和外部对象 ID 不改写。成功恢复后的请求重试返回原持久报告，不能因为刚导入了未知历史动作而失去确认成功的能力。

039 不改写已有保留数量，仅让新备份计划默认保留全部（0）；正数数量由用户显式选择。这修正了前轮默认 7 与规格默认值的偏差。暂停备份不需要再输入加密密码；它撤销排队操作并保留已接受动作的未知状态，不假称外部动作已取消。所有变化以新回归、旧 020/030/038 包兼容及原迁移校验和验证，不修改原包或已发布迁移。详见 [完整复核记录](app-spec-progress.md)。
