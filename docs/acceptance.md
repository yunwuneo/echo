## 2. 合成验收世界

建立不含真人隐私的中文世界“星港”：角色林舟、夏棠、闻砚；玩家有世界内身份“航海员”，现实资料单独设置。

- 林舟私聊得知暗号“蓝色风铃”；夏棠和闻砚不知道。
- 玩家在公共房间明确宣布“明晚九点去北塔”；角色声称“北塔已封锁”但未确认。
- 同名角色模板在第二世界“山城”创建实例，不携带星港经历。
- 玩家把偏好从“喜欢甜咖啡”改为“现在不喝咖啡”，并纠正一个模型误记日期。
- 一次已确认剧情事件被删除，另一次被用户纠正；嵌入/摘要/后台提取同时在运行。
- MCP假服务提供只读天气、创建测试提醒、模拟发送动作；可模拟执行成功但响应丢失。

固定时区、模拟时钟和随机种子。额外创建中文姓名、别名、同音词、引用/转述、假设句、否定句及剧情身份与现实身份冲突的用例。

## 4. 必须注入的故障

| 注入点                            | 不可破坏的保证                                         |
| --------------------------------- | ------------------------------------------------------ |
| 保存命令后、队列分发前崩溃        | outbox可继续分发，不丢命令                             |
| 队列分发后、标记已分发前崩溃      | 重复任务不导致重复业务提交                             |
| 世界租约过期后旧Worker返回        | fencing拒绝旧结果                                      |
| 模型输出部分文本后断流            | partial保留，终态准确，不将另一请求拼接为原请求        |
| 最终保存成功后HTTP/SSE丢失        | 客户端通过幂等请求/增量同步找回同一结果                |
| 原文删除同时记忆提取完成          | 删除epoch/修订检查阻止记忆复活                         |
| 全局预算剩余1次，两个世界同时申请 | 至多一个拿到预算；失败者不发模型请求                   |
| 审批等待期间世界变化/权限撤销     | 恢复执行前重新校验，不使用过时批准                     |
| MCP产生副作用后返回超时           | 不重发；unknown状态可见                                |
| 数据库不可用/磁盘满               | 请求明确失败或保留可恢复任务，不发送尚未保存的完成通知 |
| 备份恢复遗漏主密钥                | 凭据解密明确失败，不用空Key或错误Key继续运行           |
| 中继/APNs失效                     | 不影响权威消息保存；APNs无效token被撤销，其他设备可用  |

## 5. 性能与容量基线

起始基准：2 vCPU、4 GiB RAM，实际磁盘和网络参数记录到报告。一个owner、10个世界、每个世界最多8角色，总计10万条历史消息、2千条世界书条目、1万条记忆、2个在线客户端。

- 常规负载：持续10分钟，每分钟6条用户输入，混合后台记忆任务；使用可控假模型剥离第三方时延。
- 突发负载：10个命令同时到达，确认排队、预算、顺序和内存有界；不要求同一世界并行生成。
- 目标：持久接收ACK p95 ≤ 500ms；已提交数据对另一个在线端可见p95 ≤ 2s；单次纯检索+上下文组装p95 ≤ 300ms。
- 将模型排队/网络/首token、数据库、检索、工具和推送耗时分别报告。上面的指标不是模型生成总耗时SLA。
- 记录CPU、RSS、数据库体积增长、sync_events保留量、队列积压和索引扫描计划；发现瓶颈先优化查询/索引/批量写，不直接引入微服务。
- 至少运行24小时有界无人测试，确认预算不会跨日计算错误、任务不会指数增长、内存不会随已完成任务持续增长。

若实测基准机器达不到目标，必须给出瓶颈证据、改进方案或提高部署基线，并更新文档，不能将目标偷偷改成已达成。

## 6. 中文模型与记忆效果

建立不少于100条带标准答案的记忆查询，其中含确实不存在答案的负例；另设不少于20段多回合剧情，每段覆盖角色语气、既定关系、世界规则、秘密、纠正、引用和无人回顾。

- recall@5：有合法来源且允许当前角色读取的查询中，正确记忆进入前5候选的比例，目标 ≥ 90%。负例单独统计，不纳入recall分母。
- 权限泄漏：任何未授权内容进入角色上下文均为失败，目标0；此项用确定性数据路径测试，不能只靠模型评审。
- 来源准确性：全部自动写入条目都有有效source ID；“ID存在”之外，另人工核对候选内容是否被原文支持。无证据事实被当成确认事实写入，目标0。
- 人设一致性：按固定5分rubric评估语气、行为一致、角色区分、剧情连续性四项，平均目标 ≥ 4；严重身份/秘密串线单独判失败，不能被平均值抵消。
- 每个真实模型配置至少重复3次，记录温度等参数和离散情况；非确定性输出不用逐字golden断言。
- 至少两种实际模型配置做能力和效果验证。涉及用户付费Key的真实评估，先配置预算上限；没有Key时报告“未验证”。

## 7. Apple 与推送验收

分别在真实iPhone和Mac记录：系统版本、App版本、签名环境、通知权限、是否开启专注模式、进程状态、网络情况、APNs接受时间、可见时间、点击后的同步结果。

必须包含前台、后台、锁屏、主动强退、设备离线后恢复、拒绝通知、中继不可用、APNs token更新、sandbox/production错误配置。系统可能延迟或抑制通知；测试结果应区分“云消息已保存”“推送已受理”“设备已显示”，不能把三者混成一个成功状态。

抓取中继测试请求确认只有允许字段。投递路由不应含聊天内容、角色名、记忆、供应商Key；中继日志也遵守同样要求。

## 8. 升级、兼容与回滚

- API以`/v1`及capabilities协商兼容；破坏性变化需要新版本或明确升级门槛。
- 数据库迁移测试至少覆盖空库、前一发行schema、重复启动、迁移中断；只有一个迁移者持锁。
- 自身导出含格式版本和校验和；从前一发行格式可迁移读取。竞品兼容只覆盖声明子集。
- 高风险上线前先关自主/MCP写入开关，部署后跑冒烟再启用；保留上一镜像和备份。
- schema兼容时回退镜像；不兼容时将备份恢复至隔离环境、验证、切换；记录备份时间与可能丢失的新增数据，不能静默覆盖。
- 外部现实副作用无法靠数据库回滚撤销，需按目标系统执行补偿或人工处理。
- 用户删除内容与旧备份保留期限有明示策略；恢复旧备份时尊重可用的删除记录，并提示可能恢复已删内容的风险，不能让旧实例自动上线运行。

## 9. 整体完成定义

所有必须功能有端到端证据；确定性正确性和权限测试全部通过；真实模型及真机未验证项不得冒充通过；可以从空机器部署、双端使用、关闭客户端运行、暂停自主、导出、恢复与升级；没有已知严重数据泄漏、丢失、重复真实操作或无界消耗问题。

发行包附：版本与依赖锁定信息、部署指南、备份恢复指南、支持的模型/MCP/导入能力矩阵、已知限制、验收报告。只有达到此标准才能将T13标记完成。
